# ADR 0007: Phase 8 reports, GEDCOM and the relationship finder

Date: 2026-11-12 · Status: Proposed (awaiting review)

## What Phase 8 delivers

| Area                | Delivered                                                                                                                                                                                                                                                                                                                                     |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Relationship finder | Choose two people and see how they are related, with the path of people between them. Handles half, adoptive and step relationships; cousins of any degree and removal; relatives by marriage ("husband's sister's husband"); several true answers at once (cousins who married); and "connected through other relatives" or "not connected". |
| Advanced search     | The member list can be filtered by surname, birth years, generation, place (birth, death or hometown), living or deceased, and branch (a person and their descendants).                                                                                                                                                                       |
| GEDCOM export       | The whole tree as a GEDCOM 7 file, for the Owner and Administrators.                                                                                                                                                                                                                                                                          |
| GEDCOM import       | Upload a file (GEDCOM 7 or 5.5.1). It is read in the background and previewed: counts, warnings, and people who may already be in the tree. Nothing changes until someone confirms. The reviewer chooses for each possible duplicate: same person, someone new, or leave out.                                                                 |
| PDF reports         | Family tree chart, descendants, ancestors, individual summary, family directory and family timeline. Contributors and above can make them. Each report is made in the background and kept for 7 days.                                                                                                                                         |

## Differences from the architecture documents

| Planned                                                       | Implemented                                                                                            | Reason                                                                                                                                                                                                                                  |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `spatie/laravel-pdf` + Browsershot, Chromium in the app image | **Chromium in its own container (Gotenberg)**, called over HTTP                                        | Same engine, as approved. Keeps about 300 MB of browser and its security updates out of the app image, lets Chromium run with JavaScript off and no outside access, and lets reports use their own memory limit. No new PHP dependency. |
| The tree report renders the D3 tree from the browser          | The chart is **drawn as SVG on the server** (`TreeChart`)                                              | The PDF engine runs no scripts (deliberately). A descendant chart of up to 5 generations; larger trees are better read as the descendants outline, which has no limit of that kind.                                                     |
| Relationship labels in a translation file (EN and BM)         | English wording in `RelationshipLabeler`, run through the translator; the calculator returns structure | The structure is as planned, so Bahasa Malaysia kinship terms (`sepupu`, `dua pupu`, `pak cik`) can be added in the labeler without touching the calculation. Not translated yet, like the rest of the interface.                       |
| Redis-cached graph for the finder                             | Uses the existing graph cache (`family:{id}:graph:{version}`)                                          | Already built in Phase 4.                                                                                                                                                                                                               |
| GEDCOM import: merge decisions per duplicate                  | As planned, and **a merge only fills in what is missing**                                              | An import must never overwrite a family's own work. Matches are offered only from people with similar names; one person in the tree can be matched once.                                                                                |
| GEDCOM: sources, media, shared notes                          | **Not imported** (counted in the warnings)                                                             | There are no sources in our data model yet; media is uploaded separately with its safety checks.                                                                                                                                        |
| Report and GEDCOM limits                                      | 10 per hour per person (planned: per family)                                                           | Limits per person cannot be used up by one relative for everyone else. Also: at most 3 of a person's reports being made at once.                                                                                                        |

## Other decisions

- **The calculator is pure PHP over the family graph** (no database), tested against the fixture family (half-siblings, an adoption, a step-parent, cousins who married, in-laws). Step, foster and guardian links are only used when there is no relationship by birth or adoption. "Half" is only said when both second parents are known and different.
- **Privacy in the finder:** both people must be visible to the viewer. Someone on the path the viewer may not see appears as "Private relative", and their gender is not given away through the wording.
- **Privacy in search:** for roles that may not see living people's dates and places (Contributors, Viewers), the year and place filters only match people whose details they may see; otherwise a search for "born 1980" would reveal what the profile hides.
- **GEDCOM structure:** each partnership becomes a FAM; a child is listed under the FAM of two of its parents who are partners, and in a one-parent FAM for any other parent (for example a step-parent). How the child is related to each parent is written as `_FREL`/`_MREL` (as several other programs do), because GEDCOM's own `PEDI` cannot say "born to the father, adopted by the mother". Our other extra details use `_` tags declared in the header. Exporting, importing into an empty family and exporting again gives the same file.
- **A GEDCOM import is one transaction**, using the same Actions as manual edits. A link the tree rules refuse (a loop, a third biological parent) is skipped and listed; the rest is imported. The audit and activity logs get one line for the whole import.
- **The GEDCOM export contains everyone the exporting person may see**, which for the Owner and Administrators is everyone, including living people and private records. The page says so. Exports are written to the audit log.
- **A report is built with the privacy of the person who asked**, at the time it is made: a person who became hidden in between makes the report fail rather than appear. A report belongs to its requester alone; nobody else can list or download it.
- **Reports are printed from complete HTML** (styles inline, the profile picture embedded as data). Chromium runs with JavaScript off and may load nothing from outside, and Blade escapes every value from the family.
- **Slow jobs have their own workers:** media checks, imports and reports run on separate queues under their own Horizon supervisor (15-minute limit), so they never delay sign-in emails.
- **Cleanup:** report files are deleted after 7 days; GEDCOM uploads are deleted after the import, or after 7 days if never confirmed (`reports:purge`, nightly).

## Operating notes

- Gotenberg (Chromium) is part of `compose.yaml`. It is not reachable from outside the Docker network. Size its memory with ClamAV's when the server is chosen.
